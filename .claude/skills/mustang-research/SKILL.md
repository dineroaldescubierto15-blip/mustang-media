# Mustang research

Adapted from `instagram-research` (bradautomates/head-of-content): searches by hashtag instead of a fixed
account list, scores by engagement velocity, and prepares repost candidates with credit to the author.

## Where it runs

Every night at 04:17 UTC (05:17 Barcelona, candidates silently in Telegram before 08:00) in GitHub Actions (`.github/workflows/daily-research.yml`), because the Apify API is not reachable
from the Claude workspace. `APIFY_TOKEN` lives only as a repository secret — never write it to a file.
Run it by hand from GitHub: Actions → "Recerca diària de candidats" → Run workflow.

## Pipeline

1. `scripts/fetch_hashtags.py` — `apify/instagram-hashtag-scraper`, rotating `hashtags_per_day` of the
   hashtags in `config/sources.json`, `results_per_hashtag` each.
2. `scripts/select_candidates.py` — scores and filters, downloads the media to `media/<date>/` (public raw
   URL for the Instagram API) and writes `data/candidates/<date>.json`.

## Scoring

- engagement = likes + 3 × comments + 0.1 × views
- velocity = engagement / (hours since posting + 2) ^ 0.8 — candidates are ranked by velocity
- Filtered out: already published (`data/history.json`), same author within
  `min_days_between_same_author` days, younger than `min_age_hours` (3 h) or older than `max_age_days`
  (3 days), more than `max_views` views (300k), `excluded_authors`, our own account, and more than one
  candidate per author.
- **"Before it goes viral" strategy (Nov 2026):** Instagram treats a repost of a reel that already has
  millions of views as a duplicate and shows the original to non-followers. So we only take fresh reels
  that are gaining momentum but haven't exploded yet. The reel bank (`data/bank.json`, old mega-viral
  reels) is switched off with `use_bank: false`; set it to `true` only to go back to it.

## End card

`scripts/end_card.py` appends a 3-second black screen to every reel: the caption's question in large
white Anton capitals, a gold rule, "COMMENT BELOW ↓" and @mustangemotion (fonts in `assets/fonts/`, OFL).
The question is the caption hook without emojis (style A keeps only the question part), stored as
`end_card` in the candidate. Applied when candidates are created (`end_card: true` in config), so the
Telegram preview already shows it. `python scripts/end_card.py --queue` adds it to approved reels that
don't have it yet. If ffmpeg fails, the original video is kept.

## Captions

Generated by `scripts/caption.py`, in English for a US audience. Three styles rotate (stored as
`caption_style` in candidates and in `data/history.json`, so their results can be compared later):

- **A · Classic**: car model + an easy one-word question ("Clean or too aggressive? 👇").
- **B · Debate**: "Rate this … from 1 to 10 👇".
- **C · Community**: "Would you daily this …?" + "Tag @mustangemotion to be featured" + share prompt.

Every caption: hook → follow line → `🎥/📷 by: @author` → removal disclaimer → max **5 hashtags**
(Instagram limit since Dec 2025). The model (Dark Horse, GT500, GT350, Mach 1, Bullitt, RTR, Fox Body…)
and generation (S650/S550/S197/SN95) are detected from the original caption and hashtags; fallback
"Mustang". Never remove the credit or claim the content as ours.

## Approval and publishing

Every candidate needs Pol's approval before it is published. No exceptions.

- `telegram_send.py` sends each candidate (media + stats + status) with a single **✅ Aprovar** button,
  plus a reply with the caption draft. Unapproved candidates expire after 3 days (`expired`).
- Instant path: Telegram webhook → Make scenario "Publicar a Instagram + clics de Telegram" (route
  "Telegram") → GitHub `repository_dispatch` `telegram` → `.github/workflows/events.yml` →
  `telegram_event.py` (saves status, removes the button, updates the pinned queue) in < 1 min.
- Publish times: Make scenario "Hora de publicar" (12:00 and 19:00, America/New_York) → dispatch
  `publish` → `publish.py` → Make webhook → Instagram API. `bot.yml` (hourly-ish) is the fallback and
  does maintenance (expiry, drafts, pinned queue); it only polls `getUpdates` when no webhook is set.
- `set-webhook.yml` connects (`set`) or disconnects (`delete`) the Telegram bot from Make.
- Secrets: `APIFY_TOKEN`, `TELEGRAM_BOT_TOKEN`, `MAKE_WEBHOOK_URL`. The GitHub token used by Make lives
  only inside the Make HTTP modules.

## Cost

Apify charges per result (≈ $1.90 per 1,000 for the hashtag scraper). Defaults (3 hashtags × 20 reels a day)
stay under the free monthly credit; raise `hashtags_per_day` or `results_per_hashtag` with care.

## Telegram details

- Each candidate = media message (stats + status, ✅/❌ buttons) + a reply with the caption draft.
- After a decision the buttons are removed and the status is written on the message (final).
- A pinned message keeps the queue: approved (publish order) and pending, split into Reels and Posts.
  `/cua` in the chat re-sends and re-pins it.
- Relevance: the whole Mustang family counts (Shelby, GT350, GT500, Mach 1, Bullitt…); trucks and the
  classic Shelby Cobra are excluded unless a strong Mustang keyword appears (`config/sources.json`).
